Case study / FlowCRM

GTM Lead Qualification & Task Automation

Sales teams need a repeatable way to identify and prioritize relevant prospects, and to make sure eligible high-priority leads actually get a follow-up.

Objective

Turn a raw list of prospects into a prioritized queue where every eligible High Priority contact gets one personalized follow-up task, and no contact gets two.

Process

  1. Define the ICP for a fictional B2B SaaS company.
  2. Source 20 contacts in Apollo.
  3. Enrich and research each contact in Clay.
  4. Create lead score and priority logic.
  5. Import contacts, companies, and personalization fields into HubSpot.
  6. Create views and a workflow for eligible High Priority contacts.
  7. Create the personalized follow-up task.
  8. Update GTM Task Status to prevent duplicate tasks.

Key decisions

  • Scoring and priority live in Clay, so the logic is visible next to the enrichment data.
  • A GTM Task Status property in HubSpot holds the CRM state, which stops the workflow from creating a second task for the same contact.
  • n8n was used to prototype the flow first. The final workflow logic was built in HubSpot.

What I learned

  • A workflow without state tracking creates duplicates the moment it runs twice.
  • Prototyping in n8n made the logic clear before committing it to the CRM.
  • Personalization fields need to be designed before import, not patched after.

Case study / SmartLead

Intelligent GTM Lead Routing System

Once a lead enters a CRM, the business needs a route that is consistent and explainable, plus a follow-up action that matches it.

Rep names are fictional labels. HubSpot had one active user, so the actual task was assigned to me.

Objective

Give every lead an explainable route using only data the system can verify, and send anything uncertain to a human instead of guessing.

Process

  1. Pull 16 test contacts from Apollo.
  2. Research company HQ in Clay and normalize the country.
  3. Classify US contacts as East or West.
  4. Segment by employee count.
  5. Assign routes with deterministic formulas.
  6. Write a Routing Explanation and Routing Status for each record, and flag incomplete data for review.
  7. Import the fields into HubSpot and build a workflow that branches on Rep Assignment.

Key decisions

  • Deterministic formulas instead of judgment calls, so the same input always gives the same route.
  • A Routing Explanation on every record, so a rep can see why a lead landed with them.
  • A Needs Review route for incomplete data, so gaps are visible and not silently routed.

Validation and learnings

  • I manually enrolled one contact and confirmed the workflow created a real, route-specific task.
  • Clean country and region fields matter more than clever rules.
  • Routing needs an explicit exception path from day one.
